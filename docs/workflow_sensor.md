# QRC2026 진행 워크플로우
## 주제: 반도체 건설현장 안전 센서 최적 배치 (QUBO + QAOA)

> 멘토링 반영 핵심 원칙
> - ML은 위험 점수 산출, 양자(QAOA)는 최종 최적화 — 역할 분리
> - ML이 후보를 과도하게 줄이면 양자 역할이 작아 보임 → 양자 비중이 드러나는 구조 유지
> - 베이스라인 4개 이상 유지
> - "양자 이득" 주장 금지 → 오류 분석(Error Analysis) 중심 해석
> - 교차 플랫폼 사용은 가산점

---

## Phase 1. 문제 정의 확정 (QUBO 정식화)

- [ ] 센서 선택 변수 12개 기준 QUBO 수식 확정
  - 목적함수: 위험 가중 커버리지 최대화
  - 제약: 중복 설치 패널티, 설치 비용 최소화, 센서 수 제한
- [ ] 커버리지 표현용 보조 변수 필요 여부 결정 (큐비트 수 증가 vs 정확도)
- [ ] 핵심 목표 1~2개로 압축 (안전 + 비용). 발표용 추가 강점 1개 선정
  - 후보: 실시간 재배치 대응력, 규제/ESG 대응, 유지보수 비용 등
- [ ] MIS 접근 병행 검토 (중성원자 기반 MIS는 난이도 높음 → 준비 철저히 or QAOA 집중)

## Phase 2. 데이터 및 위험 네트워크 구성

- [ ] 반도체 건설현장 레이아웃(그리드/그래프) 정의: 위험 구역, 센서 후보 위치
- [ ] ML 기반 위험 점수 산출 모듈 구현
  - 입력: 화재/가스 확산 시나리오, 구역별 특성 (공개 데이터·시뮬레이션 데이터 활용)
  - 출력: 구역별 위험 가중치 → QUBO 계수로 주입
- [ ] 위험 점수 → QUBO 변환 파이프라인 코드화 (시나리오 바꿔 반복 실험 가능하게)

## Phase 3. 구현 — 3단계 실험 구조

### 3-1. Ideal Simulator (필수 기반)
- [ ] Qiskit으로 QAOA 구현 (p=1, p=2)
- [ ] QUBO 정합성 검증: Exact solver 결과와 소규모 문제에서 일치 확인
- [ ] 파라미터 최적화 전략 결정 (COBYLA/SPSA, 초기값, 반복 횟수)

### 3-2. Noisy Simulator (선택, 신중히)
- [ ] IonQ 실제 장비 노이즈 파라미터 확보 가능한지 확인
- [ ] 파라미터를 정확히 구할 수 없으면 과감히 축소/생략 (잘못된 노이즈 모델은 무의미 — 멘토 지적)

### 3-3. Real QPU (본선 핵심)
- [ ] 대회 제공 IonQ API 키 수령 즉시 연결 테스트
- [ ] Transpilation 레벨 최대로 설정
- [ ] Transpile 후 회로 지표 추출·기록: 큐비트 수, Circuit Depth, 2-Qubit Gate 수
- [ ] 지표 기준으로 실행 가능성 판단 → 필요 시 Error Mitigation 적용
- [ ] 샷 수·반복 횟수: 멘토 추가 답변(데이콘 확인 중) 수신 후 확정

## Phase 4. 베이스라인 비교 (4개 이상 유지)

- [ ] ① Exact Solver (brute-force/CPLEX 등 — 소규모 정답 기준)
- [ ] ② Greedy (멘토가 좋은 선택이라 평가)
- [ ] ③ Simulated Annealing
- [ ] ④ Random / 규칙 기반 배치
- [ ] 모두 돌리고 가장 잘 나온 결과 중심으로 정리 (비교군 줄이지 말 것)
- [ ] 공통 평가지표 정의: 커버리지 점수, 비용, 계산 시간, 해 품질(approximation ratio)

## Phase 5. 교차 플랫폼 활용 (가산점 요소)

- [ ] IonQ 직접 API + Amazon Braket + 로컬 시뮬레이터 교차 실행
- [ ] 여유 시 스폰서 플랫폼(Pasqal/Quandela) 추가 검토 → 시상 관점 유리
- [ ] 플랫폼별 결과·차이 기록 (발표 자료용)

## Phase 6. 결과 분석 및 해석

- [ ] QPU 결과가 고전 대비 낮아도 OK — 원인 분석이 점수
  - 노이즈 요인 분해: 게이트 에러, 디코히런스, 샷 노이즈
  - 회로 깊이·2큐비트 게이트 수와 성능 저하의 상관 분석
- [ ] "양자 이득" 표현 금지 → "NISQ 한계 내 가능성 검증" 프레임 사용
- [ ] 고전적 한계(조합 폭발, 실시간성)와 양자 접근의 확장 가능성 논리 정리

## Phase 7. 발표 준비

- [ ] 스토리라인: 문제 정의 → Quantum Reframing → 구현 → 비교 검증 → 한계 분석 (대회 평가 기준 순서)
- [ ] 차별점 강조: 구체성(강점으로 이미 평가받음) + 추가 강점 1개 + 교차 플랫폼
- [ ] 예상 질문 대비: "비교군이 왜 이것뿐인가", "노이즈 모델 근거", "실용화 가능성"
- [ ] 데모/시각화: 센서 배치 결과 맵, 위험 히트맵, 알고리즘별 성능 비교 차트

---

## 미해결 확인 사항 (팀장 액션)

1. 본선 권장 QAOA 깊이·샷 수·반복 횟수 → 멘토 답변 대기 (팀장 메일 확인)
2. 기획서 양식·예선 마감일 → 대회 게시판 확인
3. IonQ API 키 배포 시점 확인
4. 교육영상 3, 4회 (7.24 업데이트) 시청

## 권장 진행 순서 요약

```
QUBO 확정 → 위험 네트워크/ML 모듈 → Ideal Sim 검증
→ 베이스라인 4종 실행 → (Noisy Sim) → Real QPU 실행
→ 오류 분석 → 발표 자료
```
