## 0. 설계 원칙 — 먼저 합의해야 하는 것 (가장 중요)

**공개 데이터셋에는 "위험도" 정답 라벨이 없다.** CubiCasa5K·Structured3D는 주거·실내 데이터이고 라벨은 방 유형·구조·semantic 픽셀뿐이다. 따라서 "AI가 위험을 예측한다"고 말하려면 없는 라벨을 만들어야 하고, 그건 근거 없는 학습이 된다.

이 프로젝트의 정직한 구성은 역할을 둘로 나누는 것이다.

| 층 | 담당 | 근거 | 검증 방법 |
|---|---|---|---|
| **ML (지도학습)** | 도면 이미지 → 구역 분할·유형 분류·문/창 인식 | CubiCasa5K SVG 주석에 **정답 라벨 존재**, 공식 분할 4200/400/400 | test 400장 IoU·정확도 |
| **위험 인자 (규칙+물리)** | 구역 유형·기하·기상 → 위험 점수 r_z, 간선 위험 w_e | 산업안전보건규칙(P4), 사고 사례(P3), 기상청 실측 풍향·풍속 | 민감도 분석·정성 검증 |

즉 **ML이 학습하는 대상은 "위험"이 아니라 "도면 구조 인식"**이고, 위험은 그 인식 결과 위에 규칙·물리·기상으로 계산한다. 이렇게 하면 멘토 지적("근거 없는 모델 금지", "ML이 양자 역할을 잠식하지 않게")을 모두 만족하고, 발표에서 "라벨이 없는데 어떻게 학습했나"라는 질문에 방어할 수 있다.

## 1. 파트 1 단계별 워크플로우

### P1-1. 데이터 정리 (담당: Codex, 1일)

- **CubiCasa5K** (`Data/10_cubicasa5k_inventory_20260726`): ML 학습 정본. `ml_recommended=TRUE` 4,992장, 공식 분할 유지. SVG에서 방 폴리곤·유형·문·창 좌표를 학습 라벨로 추출 → CSV/NPZ 스키마 정리 요청.
- **Structured3D** (`Data/09_structured3d_preprocessed_20260726`): 2차 도메인 검증용. `room_semantic_label_stats.csv`의 라벨 40여종 픽셀 통계를 사용해 도메인 이전(domain transfer) 테스트. **현재 미사용 상태인 이 데이터셋의 용도를 여기서 확정한다.**
- 요청 산출물: `Data/11_ml_labels_*/` — (a) 이미지 경로, (b) 방 폴리곤 좌표(픽셀·미터 환산 계수 포함), (c) 방 유형 라벨 ID, (d) 문·창 좌표, (e) 공식 분할 플래그.

### P1-2. ML 모듈 A — 도면 → 구역 인식 (담당: Claude, 2~3일)

- 입력: 평면도 PNG. 출력: 구역 폴리곤 + 유형 + 문/창 위치.
- 1차 접근: 경량 U-Net 계열 세그멘테이션(방 영역) + 소형 분류기(유형). 학습은 CubiCasa 공식 train, 검증 val, 최종 보고는 test 400장만 사용.
- **폴백 필수**: 학습이 기한 내 목표 성능에 못 미치면 SVG 주석 직접 파싱 경로로 전환한다(이미 `cubicasa5k_ingest.py`에 구현됨). 파이프라인은 ML 없이도 끝까지 동작해야 한다 — 일정 리스크 차단.
- 평가지표: 방 영역 IoU, 유형 정확도, 문 검출 재현율. 실패 사례 이미지를 발표용으로 남긴다(과장 방지).

### P1-3. 구역 그래프 구성 (담당: Claude, 1일)

- ML 출력 → 그래프: 노드=구역, 간선=문·개구부로 연결된 인접 관계.
- 간선 속성: 통로 길이(m), 통로 폭(m), 출구 노드 여부, 막힌 통로(dead-end) 플래그, 분기 수.
- 출력 스키마: `zones.csv`(id, 유형, 면적, 중심좌표), `edges.csv`(from, to, 길이, 폭), `exits.csv`.
- 이 그래프가 **센서 QUBO와 대피 QUBO의 공통 기반**이 된다.

### P1-4. 위험 인자 산출 — 기상 연결 (담당: Claude, 2일) ★ 핵심

기존 `src/risk_model.py`를 확장한다. 현재는 구역 유형×사고 심각도 + 풍속 이진 보정(≥8 m/s 시 ×1.10)뿐이며, **풍향은 수집만 하고 쓰지 않는다**. 이걸 방향성 모델로 고도화한다.

- **정적 인자**: 구역 유형 노출도(기존), 면적, 출구까지 최단거리, dead-end 여부, 분기 수, 문 폭(병목).
- **동적 인자 — 기상 연결**:
  - 기상청 `wd_deg`(풍향)·`ws_ms`(풍속)로 확산 방향 벡터 생성.
  - 발화·누출 가정 지점에서 **풍하측(downwind) 구역에 방향성 가중** 부여. 가중치는 풍향과 구역 방위각의 코사인 유사도 × 풍속 계수.
  - 가스 비중(P4 근거: 수소 부력 상승, 실란 등)에 따라 상·하층 보정 분리.
  - 무풍 시 등방 확산으로 축퇴 → 기존 결과와 하위 호환.
- **출력 2종**:
  - `r_z` — 구역 위험 점수. **센서 QUBO가 이미 쓰는 값** → 인터페이스 변경 없이 교체 가능.
  - `w_e` — 간선(통로) 통과 위험. **대피 QUBO의 신규 입력.** 연기 확산 방향·통로 폭·거리 반영.
- 모든 가중치는 파일 내 상수로 분리하고 "모델링 가정"으로 명시. CFD가 아님을 결과에 기록.

### P1-5. 검증 (담당: Claude, 1일)

- 기상 시나리오 격자: 무풍 / 약풍(2 m/s) / 강풍(10 m/s) × 풍향 4방위 = 9종에서 `r_z` 민감도 측정.
- 정성 검증: 위험 히트맵을 도면 위에 렌더 → 풍하측이 실제로 붉어지는지 눈으로 확인(자동 판정 + 이미지 저장).
- 회귀 검증: 무풍 조건에서 기존 `run_experiment.py` 결과와 일치하는지 확인(하위 호환 보장).
- 한계 명시: 2D 등방 근사, 벽 차폐·천장고·공조 미반영, CFD 아님.

## 2. 파트 2 결합 설계 — 어떻게 합칠 것인가

**연결점은 단 하나로 명확하다: 파트 1이 만든 `r_z`와 `w_e`를 두 양자 최적화가 공유한다.**

```
        [파트 1]  도면 PNG ──ML──> 구역·문 인식 ──> 구역 그래프
                                    +  기상(풍향·풍속) + 법규(P4) + 사고사례(P3)
                                              ↓
                                  위험 인자  r_z (구역) ·  w_e (통로)
                                       ↙                    ↘
        [파트 2-A] 센서 배치 QUBO (기존, 완성)      [파트 2-B] 대피 경로 QUBO (신규)
         위험가중 커버리지 − 비용 − 중복             대피시간 + 위험노출(w_e) + 혼잡도
                    ↘                                        ↙
                        결합: 센서 커버리지 = 위험 관측 신뢰도
                              → 미커버 구역은 보수적 가중으로 대피 계산
```

### 결합 방식 3안

- **결합 A — 순차 결합 (권장, 기획서 기준선)**
  센서 배치를 먼저 최적화 → 커버된 구역은 위험 관측이 신뢰 가능, 미커버 구역은 불확실 → 대피 경로는 미커버 구역을 보수적으로(위험 상향) 취급.
  스토리: **"센서는 대피 시스템의 눈이다. 어디를 보는지가 어디로 대피할지를 결정한다."** 두 주제가 억지 결합이 아니라 인과로 연결된다.
  구현 부담 낮음, 큐비트 수 그대로.

- **결합 B — 통합 QUBO (toy 시연 + 확장성 이론)**
  센서 변수 x_j와 경로 변수 y_p를 한 QUBO에 넣고 교차항으로 "관측되지 않은 경로로 대피 시 패널티"를 표현. 변수 수가 늘어 큐비트가 급증 → **소규모 toy(예: 구역 6·후보 6·작업자 2)로 정합성만 시연**하고, 산업 규모 확장 시 자원 증가를 이론 비교로 제시. 대회 평가의 `산업 적용 가능성·확장성`(25점) 대응.

- **결합 C — 반복 결합 (본선 확장 후보)**
  대피 경로에서 노출 위험이 큰 통로를 찾아 센서 배치를 재조정하는 양방향 반복. 시간이 남을 때만.

### 대피 QUBO 정식화 초안 (파트 2-B)

- 변수: 작업자 w의 후보 경로 p 선택 y_{w,p} ∈ {0,1} (경로 후보는 그래프에서 k-shortest로 사전 생성 → 변수 수 통제).
- 목적: Σ 대피시간(경로 길이/이동속도) + λ₁ Σ 위험노출(경로 상 w_e 합) + λ₂ 혼잡도(같은 통로 공유 시 이차 패널티).
- 제약: 작업자당 경로 정확히 1개 (Σ_p y_{w,p} − 1)², 통로 수용량 초과 패널티.
- 베이스라인 4종 대응: Dijkstra(최단거리), 위험가중 Dijkstra, Exact 전수, Simulated Annealing → 기존 `baselines.py` 인터페이스 재사용.
- 혼잡도 이차항이 고전 최단경로로 분해되지 않는 지점이 **양자 최적화의 정당한 근거**다(각 작업자 독립 최단경로 ≠ 전체 최적).
