# Quantum SafeON

**위험 인자 기반 대피 경로 + 안전 센서 최적 배치 통합 시스템 (QUBO + QAOA)**

Quantum Reframing Challenge 2026 · 자유 주제 트랙

> 도면과 기상 데이터로 현장의 위험을 계산하고, 그 위험을 두 개의 양자 최적화가 공유한다.
> **센서는 대피 시스템의 눈이다. 어디를 보는지가 어디로 대피할지를 결정한다.**

---

## 1. 문제와 접근

반도체 건설현장에서 화재·가스 누출이 발생하면 최단 거리가 항상 가장 안전한 대피 경로는 아니다. 연기 확산 방향, 유독가스, 통로 폐쇄가 실시간으로 바뀌기 때문이다. 동시에, 위험을 감지할 센서를 **어디에 설치하느냐**가 이 판단의 정보 품질을 결정한다.

이 프로젝트는 두 문제를 하나의 위험 인자로 연결한다.

```
[파트 1]  도면 이미지 ──ML──> 구역·문 인식 ──> 구역 그래프
                              + 기상(풍향·풍속) + 법규 + 사고사례
                                        ↓
                         위험 인자  r_z (구역) ·  w_e (통로)
                              ↙                        ↘
[파트 2-A] 센서 배치 QUBO (구현 완료)      [파트 2-B] 대피 경로 QUBO (설계 완료)
 위험가중 커버리지 − 비용 − 중복 설치       대피시간 + 위험노출 + 혼잡도
                     ↘                        ↙
              결합 A: 센서 커버리지 = 위험 관측 신뢰도
                     → 미커버 구역은 보수적 가중으로 대피 계산
```

### 설계 원칙 — ML이 학습하는 것은 "위험"이 아니다

공개 데이터셋에는 위험도 정답 라벨이 존재하지 않는다. 따라서 역할을 분리했다.

| 층 | 담당 | 근거 |
|---|---|---|
| **ML (지도학습)** | 도면 → 구역 분할·유형 분류·문/창 인식 | CubiCasa5K SVG 주석에 **실제 정답 라벨 존재**, 공식 분할 4200/400/400 |
| **위험 인자 (규칙+물리)** | 구역 유형·기하·기상 → `r_z`, `w_e` | 산업안전보건규칙, 사고 조사 사례, 기상청 실측 |

즉 **AI는 도면을 읽고, 규칙과 기상이 위험을 계산한다.** 없는 라벨을 만들어 학습하지 않는다.

## 3. 실행 방법

### 3-1. 환경 구성

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows / Linux·macOS: source .venv/bin/activate
pip install -r requirements.txt
```

API 키는 `.env` 파일에만 둔다 (`.env.example` 참고, git 추적 제외).

```
KMA_API_KEY=<기상청 API허브 키>
IONQ_API_KEY=<IonQ 키>
```

### 3-2. 전체 실험 파이프라인

```bash
python src/weather_kma.py        # (선택) 기상청 풍향·풍속 캐시 생성
python src/run_experiment.py     # QUBO + 베이스라인 4종 + QAOA, 반경 3종
```

출력: `results/experiment_results.json`, `results/실험결과_요약.md`

### 3-3. UI 데모 (권장 시연 경로)

```bash
python src/ui/server.py          # → http://localhost:8788
```

접속하면 **예시 도면과 센서 후보 12개가 자동으로 로드**되므로, 도면 없이 [QUBO + QAOA 최적화 실행] 클릭만으로 시연할 수 있다. 직접 도면(PNG/JPG)을 올리면 대체된다.

- 도면 클릭 → 센서 후보 추가 (2~14개)
- 반경: 시나리오 자동(3/5/8 m) 또는 수동
- 백엔드: Ideal Simulator(즉시) 또는 IonQ 클라우드 시뮬레이터(무료)
- 결과: 선택 센서 초록 ✓ / 제외 회색, 취약 구역 붉은 점선, **선택·제외 이유를 한국어 해설로 출력**

### 3-4. IonQ 실행

```bash
python src/ionq_connect_test.py          # 연결 검증 (인증→transpile→시뮬레이터 100샷, 무료)
python src/run_qpu_experiment.py         # 최적 파라미터 회로 제출 (클라우드 시뮬레이터, 무료)
python src/run_qpu_experiment.py --qpu aria-1   # 실제 QPU (유료, 'YES' 확인 필요)
python src/run_qpu_experiment.py --fetch        # 큐 대기 job 결과 회수·분석
```

> 실제 QPU 제출은 비용이 발생한다. UI 서버에는 QPU 호출 경로가 없다(비용 차단).

### 3-5. 검증

```bash
python src/verify_cubicasa5k_e2e.py      # PNG→배치→JSON→커버리지→QUBO 전체 흐름 6항목 검증
```

## 4. 결과 및 데이터 분석

### 4-1. 센서 배치 최적화 (K=6, hard 커버율 τ=0.27, 기상 반영)

부분면적 커버리지(원∩사각형 면적비) 기준, 반경 시나리오 3종:

| 시나리오 | 최적 배치 | 가중 커버리지 | 장비가 합계 | 법적 hard 제약 |
|---|---|---|---|---|
| low (3 m) | C04·C05·C07·C08·C09·C10 | 0.197 | 약 617만 원 | 충족 |
| nominal (5 m) | C03·C04·C05·C08·C09·C10 | 0.510 | 약 722만 원 | 충족 |
| high (8 m) | C03·C04·C05·C08·C09·C10 | 0.682 | 약 722만 원 | 충족 |

**해석**: 반경이 작으면 고가 후보 C03 대신 저가 C07이 선택된다. 감지 반경 가정이 배치와 비용을 실제로 바꾼다는 점이 민감도 분석의 핵심 결과다.

### 4-2. 고전 베이스라인 vs 양자

베이스라인 4종(Exact·Greedy·SA·Random) 모두 Exact와 동일한 최적해에 도달했다. **12변수 규모에서는 당연한 결과이며, 이를 "양자 우위 없음"이 아니라 정식화 검증으로 해석한다.** 산업 규모 확장 시의 계산 복잡도·자원 증가는 이론 비교로 별도 제시한다.

QAOA (Ideal Simulator, 2048샷):

| 시나리오 | p=1 근사비 | p=2 근사비 | 최적해 확률 증폭 (균등 대비) |
|---|---|---|---|
| low | 0.878 | 0.913 | 최대 16.6배 |
| nominal | 0.908 | 0.877 | 3.8배 |
| high | 0.921 | 0.902 | 3.5배 |

### 4-3. IonQ 클라우드 시뮬레이터 실행 결과

Ideal에서 최적화한 (γ, β)를 고정 파라미터로 제출 (nominal, 1024샷):

| 회로 | 최적해 발견 | P(최적해) | 균등 대비 | 최소 에너지 |
|---|---|---|---|---|
| p=1 | **O** | 0.000977 | 4.0배 | −2.36131 (= Exact) |
| p=2 | X | 0.0 | — | −2.270955 |

**분석**: p=1의 증폭률 4.0배는 Ideal 예측(3.8배)과 정합하며, 회로 변환·비트 순서·제출 경로가 모두 올바름을 입증한다. p=2 미발견은 Ideal 기준 기대 관측 횟수가 1024샷 중 약 0.5회이므로 **통계적으로 자연스러운 결과이며 오류가 아니다.** 실기 QPU 단계에서는 p=1 중심 또는 샷 수 증대 전략이 타당하다.

회로 지표 (p=1, optimization_level=3): 12큐비트, depth 24, 2-qubit 게이트 66개. IonQ Aria 공개 2Q 오류율 0.4% 기준 추정 회로 충실도는 p=1 약 0.73, p=2 약 0.56으로, NISQ 한계 분석에 적합한 규모다.

### 4-4. 기상 연동

기상청 API허브 실측(관측소 108, 2026-07-26 20:00 KST: 풍향 27°, 풍속 1.8 m/s)을 위험 점수에 반영했다. 현재 강풍 기준(≥8 m/s) 미만이라 보정 계수는 1.0이며 배치는 변하지 않았다. **풍향을 이용한 풍하측 방향성 가중 모델이 다음 단계 작업이다.**

### 4-5. UI ↔ 파이프라인 연동 검증

`verify_cubicasa5k_e2e.py` 6개 항목 **전부 PASS**: PNG 로드 / UI JSON 센서 좌표 일치 / 커버리지 독립 재계산 오차 0.0000 / QUBO Exact 최적성 / ML 권장·공식 분할 유지 / 데이터 출처 표기 유지.

## 6. 데이터 출처와 한계

전체 출처·라이선스는 [`NOTICE_DATA.md`](NOTICE_DATA.md) 참조.

**반드시 유의할 한계** (발표·재사용 시 그대로 표기):

- 현장 레이아웃은 **실제 반도체 팹 도면이 아니라 공개 자료 기반 합성 레이아웃**이다 (`data_status=synthetic_*`).
- 감지 반경 3/5/8 m는 제조사 성능 보증값이나 법정 기준이 아니라 **민감도 분석용 모델링 가정**이다.
- 커버리지는 2D 등방성 원형 가정이며 벽 차폐·천장고·공조·풍향 확산을 반영하지 않는다.
- 사고 시나리오는 소표본 사례표로, 확률 학습용 데이터가 아니라 규칙 기반 위험 점수의 근거로만 사용한다.
- 데모 평면도(CubiCasa5K)는 **주거용 공개 데이터셋**이며 반도체 현장 근거가 아니다. 픽셀·좌표를 실제 미터나 설치 근거로 직접 해석하면 안 된다.
- IonQ 노이즈 값은 공개 평균값이므로 Noisy 시뮬레이션은 교육용 근사로 한정하고 실기 calibration을 우선한다.
